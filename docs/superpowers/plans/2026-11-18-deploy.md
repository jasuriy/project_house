# Deploy for Friends' Testing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the code deployable to Vercel + Modal + Neon + R2, then deploy it with Bek's
accounts so friends can use it.

**Architecture:**
- Each production behaviour is behind a setting whose default keeps today's local behaviour:
  - media backend `disk|r2`;
  - email login on/off;
  - the seed override.
- A Modal entry file wraps the existing FastAPI app.
- The frontend gets a build flag for GitHub-only sign-in, a feedback footer and a region.

**Tech Stack:** FastAPI, SQLAlchemy async, boto3 (S3 API for R2), Modal, Next.js 16 on Vercel.

**Spec:** `docs/superpowers/specs/2026-11-18-deploy-design.md`

## Global Constraints

- Defaults keep local development and every existing test unchanged:
  - `MEDIA_BACKEND=disk`;
  - `EMAIL_LOGIN_ENABLED=true`;
  - `NEXT_PUBLIC_EMAIL_LOGIN` unset, which means on.
- No secret in the repository, tests, logs or chat; secrets live in the Modal secret and Vercel env.
- The seed tool still refuses `APP_ENV=production` unless `--allow-production` and `--owner` are
  both given.
- `Cache-Control: private, no-store` on every `/api/*` response except `/api/v1/media/*`, which keeps
  `public, max-age=31536000, immutable`.
- Storage calls never block the event loop.
- Uzbek texts use ʻ and ʼ, never `'`. No emoji anywhere.
- Gates:
  - backend: `pytest -q`, `ruff check .`, `ruff format --check .` (main venv,
    TEST_DATABASE_URL=.../projecthouse_test);
  - frontend: `npx eslint src tests`, `npx vitest run`, `next build`.
- Bek's local site (3000/8000) and DB `projecthouse` are not touched.

## Review Focus

1. **A cached API answer served to the wrong person through Vercel.** Covered by Task 1 tests
   (`/api/v1/me/saved` is `private, no-store`) and the live check (Task 5).
2. **R2 errors on upload.** An R2 failure must give an error answer, never a stuck request or a
   half-saved upload row. Task 2 test: the fake client raises, the upload answers 5xx, and no
   `uploads` row remains.
3. **A media key that is not ours.** Path traversal or a wrong format gets a 404 before any R2 call.
   Task 2 test.
4. **Email routes in production.** Every email route answers 404 `email_login_disabled`, while
   `/auth/me`, logout and OAuth still work. Task 1 test.
5. **A friend lands on /forgot-password or /verify-email from an old link while email is off.**
   They are sent to /login, with no broken form. Task 4 test.
